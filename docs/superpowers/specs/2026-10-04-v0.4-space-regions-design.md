# V0.4 Space / Region Semantics

Issue #7 is the approved scope. Entity identity continues to resolve physical source objects; a separately versioned registry resolves spatial regions by actual hit coordinates. No authoritative geometry is split, tagged, or saved.

## Contracts and boundaries

Add spaces, project and semantic-status V1 contracts and an optional spatial_context on existing ContextPacket V1. Registries bind design, applicable model revision/SHA, evidence resource revision/SHA, level and coordinate frame/unit/up axis. Simple polygon prisms have finite non-self-intersecting footprints and positive height. Space IDs are unique. Human verification records are required for verified regions; source confidence never implicitly becomes approval.

The lightweight project descriptor inventories sources, levels and required coverage domains. Readiness is computed, not trusted from a claimed status: READY requires verified region coverage for every declared level/domain, known source linkage and no positive-volume overlap. Candidates, missing domains/levels and incomplete coverage yield actionable PARTIAL diagnostics. Absent usable regions yields BLOCKED_FOR_SPATIAL_CONTEXT. A source adapter that cannot extract trustworthy regions must explicitly request normalized polygons or manual supplementation.

## Lookup

Containment includes polygon and height boundaries with documented numerical tolerance. Shared boundaries return all matches and are ambiguous. Candidate-only containment remains unresolved until reviewed. Exact requires one verified containing space and no competing region. Point resolution is independent of entity ID; entity.room_id remains unchanged. A list selection has no hit and cannot fabricate spatial location.

Registry queries use a declared frame: source-space conversion is supplied only by the existing declared Blender conversion; generic proxies may query a matching proxy frame. Unit conversions preserve explicit axis/frame semantics. Mismatched design/model revision/SHA or frame refuses spatial lookup and exposes a gap. Packets include the registry artifact byte hash, evidence provenance, query point, readiness and resolution. Old ContextPackets without spatial_context remain valid.

## Ingestion

Explicit normalized region evidence from IFC/FreeCAD/authored JSON is preferred to CAD candidates and model geometry candidates. Native source inventory is read-only and reports capabilities/limitations. The initial supplementation workflow imports edited/authored Space Registry JSON and re-runs schema, provenance, overlap and coverage validation. No CAD editor or native geometry reconstruction suite is added.

## Real acceptance

C-Type sources include FreeCAD, IFC, CAD, task01 room polygons, semantic schedules and R4. Existing task01 room polygons explicitly describe themselves as approximate label regions, cross some walls and include corridor in the lounge label. They must remain candidates, not be silently marked verified. R4 floor/transition reports provide model-specific geometric evidence. Prepare a reviewable region proposal with source hashes and diagnostics, then obtain missing human confirmation if the existing evidence cannot establish verified regions. Required end-to-end evidence is two real viewport clicks on the same continuous R4 floor with distinct spaces and two packet-only independent agent resolutions. Production evidence stays under ignored task-output.
