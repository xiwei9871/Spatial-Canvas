# V0.5 General Relationship Graph

Issue #9 is the approved scope. Graphs are external artifacts; frozen source files are never tagged or saved. The graph distinguishes physical connections, membership, embedding, adjacency and transitions; no generic related_to is introduced.

## Contract

Nodes use globally unique node_id and entity/space/level/component_group kind, display name and exact resource/revision/SHA linkage. Entity/space/level nodes carry their corresponding semantic ID; entities also carry native locators. Graph sources inventory all resources, including model and space registry bytes. Stable edge IDs persist independently of traversal. Edges carry typed from/to or a transition endpoint set, provenance method/evidence/source hash, verification (verified/candidate/rejected), confidence and optional geometric evidence. Verified inferred edges require an explicit reviewer decision; naming-only evidence cannot be verified. Symmetric edges use canonical sorted endpoints. contains is the inverse view of part_of, normalized for duplicate/cycle checks. Embedded_in is separate. transition_between has one transition subject and >=2 distinct space/level endpoints.

## Core and integrity

Runtime validation rejects missing/duplicate nodes and edges, duplicate semantic relations, wrong node kinds, self relations, hierarchy/embedding cycles and mismatched source evidence. Query APIs preserve typed edges, incoming direction, inverse hierarchy and review state. getConnected does not traverse component membership. Parent group traversal is bounded and explicit. ContextPacket includes direct subject/primary-space edges, ancestors and ancestor embedding/transition edges with original ownership; it never fabricates a subject embedded_in fact from a parent's edge. Nodes/edges are compact and capped with a truncation diagnostic.

## Readiness and inference

Separate component_hierarchy, physical_connectivity, space_adjacency and transition_graph capabilities use READY/PARTIAL/BLOCKED/NOT_REQUESTED. Completeness is scoped to declared required node/type pairs, not inferred from one existing edge; unchecked capabilities are unavailable, never global READY. Missing graph or unresolved transition endpoint produces actionable gaps. Source inventory prefers explicit authored/IFC/FreeCAD relationships to hierarchy then geometry candidates. Read-only Blender extraction supplies native parent/group membership and evaluated AABBs; AABB/contact/boundary/vertical evidence only produces candidates. No near-distance-only verified adjacency. Review approve/reject saves a new graph revision with stable IDs/provenance retained.

## Integration and real gates

Existing ContextPacket V1 gains optional relationships; semantic status gains optional capability status. Import graph JSON with exact byte SHA alongside project/space registry; model/design/hash and node locators must match the loaded proxy, and space refs must match loaded registry SHA/revision. Invalid/stale graphs yield unavailable relation context, leaving physical selection usable. UI labels verified/candidate/rejected and direct relation vs ancestor-owned relation separately.

Non-C-Type fixture covers two spaces/door/wall/assembly/direct contact/near-unrelated mesh. C-Type real dogfood builds evidence-backed sink membership and four basin-wall connections, ancestor sink embedding, faucet group-only links and explicit missing plumbing; door sides/opening evidence are verified only where valid reviewed regions exist, otherwise candidates with named gaps. Stair endpoints remain candidates if not reviewed; wall adjacency requires a boundary/contact test. Actual browser clicks capture sink/door/stair/wall packets, then three isolated agents read only sink/door/stair packets. R4 SHA/mtime and all predecessor gates remain unchanged/passing. No live sync, graph DB, CAD solver, plumbing reconstruction or source mutation.
