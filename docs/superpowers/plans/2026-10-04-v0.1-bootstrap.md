# Spatial Canvas V0.1 implementation plan

**Goal:** Deliver Issue #1 as a runnable local workspace and a reviewable PR.

**Architecture:** Protocol contracts are independent of Three.js. Pure core state produces validated events. Viewer maps node metadata and renders derived artifacts. Workspace connects local files to these boundaries.

**Tech stack:** TypeScript, Vite, Three.js, Zod, Vitest, ESLint.

User has authorized implementation and PR delivery; execute inline and keep review gates at the completed PR.

- [x] Protocol: write rejection/acceptance tests, observe failures, implement Zod contracts, and generate committed JSON Schema in `schemas/`. Verify `npm test -- tests/protocol.test.ts`.
- [x] GLB identity: write tests for duplicate/missing IDs, revision mismatch, inherited metadata, malformed containers, and external dependencies. Implement preflight and semantic binding. Verify `npm test -- tests/glb.test.ts`.
- [x] Core: write selection/reload/intent tests, observe failures, then implement pure state and request helpers. Verify `npm test -- tests/core.test.ts`.
- [x] Fixture: generate a self-contained cube-based living room GLB from a committed JSON source specification, with deterministic IDs and source SHA. Commit full/task manifests and a regeneration script.
- [x] Viewer/workspace: implement orbit controls, raycast selection, highlight, spatial inspector, file-pair import, reload, entity search, request form, and event export. Verify through the local browser.
- [x] Docs/CI: document schema evolution, authority boundaries, producer contract, adapter skeleton, fixture ownership, quick start, and acceptance steps; add CI running `npm ci` and `npm run check`.
- [x] Review: run lint/typecheck/tests/build and inspect complete issue coverage and architecture boundaries.
- [ ] Delivery: implementation branch can be pushed over existing SSH authentication; PR creation and chat attachment require GitHub API authentication (`gh auth login`).
